从 Wildmeerkat lite 借鉴的 VEMO 设计

本次重构把“安装是什么、如何验证、如何恢复”的责任从分散脚本中收拢成共享服务，并建立独立的图形入口和文档入口。VEMO 的政策、风险矩阵、机器门禁和验收模型继续由现有治理核心负责。

参考依据

实际阅读的参考快照：

  • Wildmeerkat lite，commit ea69176306d3e87d3c2200adba6ed3d9a1c4762e。
  • master_spec.md：原则、职责分层、统一安装生命周期、安装后验证、向后兼容和恢复要求。
  • 部署模型与 bootstrap.py：项目隔离、预检查、幂等接入与配置保全。
  • AIIGovernance-docs，commit e3f2f4bef0530045e1e776e96e80c8663b1baa70，重点阅读 app/content/getting-started.tsx 和 maintenance.tsx 的安装、验证、使用、维护说明。

框架源码与安装器、发行包、文档分别维护是参考项目明确记录的边界。此次研究读取了治理源码与文档源码，未把未检查的私有安装器实现当作已验证事实。实现代码为 VEMO 新写，没有复制参考框架的业务法或安装器源码。

采用与调整

参考设计 VEMO 中的落点 取舍
原则、规范、执行分层 specs/、enforcement/ 与 bin/vemo_setup/ 各自负责政策、执行、安装 UI 不产生第二套政策判定
统一安装生命周期 CLI 和 UI 共用 plan_install/apply_install/check_install/plan_uninstall/uninstall/recover 历史 start/init 保留兼容；新接入走 setup
项目级独立安装 文件保存在选定仓库，清单记录实际载荷摘要 使用受管文件部署，保持现有相对路径；未引入 submodule 和便携 Python
安装完成需要证据 执行 CLI/selfcheck/extensions 和 Git 接线检查 本地检查与远端 CI/宿主实际加载分别说明
保全用户配置 项目入口采用标记块，JSON hooks 做结构合并，其他同名文件冲突即停止 不对用户设置做盲目覆盖
失败可恢复 原始内容备份、逐文件摘要、原子写入、事务日志 强制中断后可恢复；后续修改不会被回滚覆盖
安装文档面向用户目标 安装、使用、设计各有入口，UI 内置离线帮助 不要求新用户先读全部治理规范
只观察的产品 hooks VEMO 继续执行既有拦截与 Git/CI 门禁 参考项目 0.6 的“不做治理层拒绝”与 VEMO 现有约束不同，未迁移该政策

浏览器只有已列出的安装生命周期接口，不能提交 shell 命令、关闭门禁、伪造业务验收或开启全自动模式。服务仅绑定回环地址，校验 Host、Origin、随机会话令牌和请求长度；静态页面采用明确文件白名单。令牌在 URL fragment 中传递，不进入 HTTP 路径或访问日志。

项目执行检查前会核对已安装运行文件的摘要。Python 诊断使用只含这些已核对内容的临时运行目录，并关闭项目路径、用户 site 和启动钩子的隐式导入；项目中同名模块不会被安装诊断执行。诊断仍读取实际目标项目的配置与接线。清单是本机合作环境下的恢复和溯源记录，不是对恶意本机管理员的签名认证，也不替代 VEMO 的业务任务验收回执或远端 CI。

安装清单与恢复边界

每个部署记录版本、源码基础 commit、实际载荷摘要、文件安装后摘要及安装前内容。版本字符串可相同而工作树内容不同，因此不能只按版本号判断是否相同安装。

安装与卸载先写入可恢复日志，再逐文件原子替换；检查失败触发回退。回退只处理当前内容仍匹配该事务的文件。事务被强制终止时保留日志，不把“进程退出”当作安装成功。

升级只覆盖清单确认仍未改变的受管文件。卸载遇到任何安装后修改会整体停止，以保持 hooks 与运行文件相互完整。动态任务、judge 流水、验收日志不进入安装载荷清单。

CI 的部署依赖也属于载荷契约：安装包携带 conformance runner 和依赖的文档、资源及测试。框架测试部署到 eval/tests/，CI 不把业务测试目录当作框架测试集；默认接入场景使用隔离数据测试，避免把业务项目合法的自定义 preset 当成框架失败。

当前交付边界

  • 安装和使用界面采用本地浏览器，运行需要主机 Python、Git、Bash；没有冒充已发行的独立桌面安装包。
  • 支持独立 Git 仓库；worktree/submodule 和自定义 hooksPath 需要后续平台适配。
  • 不包含账号绑定、机器人、云端同步、便携解释器、自动联网升级或自动配置远端分支保护。
  • Linux 上验证了 CLI 和浏览器流程；Windows/macOS 尚待各自平台验收。

这些边界体现在错误信息、安装前检查和文档中。后续扩展应复用安装服务与载荷清单，增加实际平台验收，而不复制一份安装逻辑。
