VEMO 使用指南

VEMO 的核心只有 Policy、Task、Gate、Verify、Evidence 五个概念。安装后，规则和证据保存在目标项目中，AI 助手、Git hooks 和 CI 使用同一个 evaluator。

第一次使用

在目标项目根目录运行：

python3 bin/vemo status
python3 bin/vemo task create --id T-feature --scope 'src/**' 'tests/**'

task create 只会替换未修改的发行占位任务，不会覆盖真实授权。使用 python3 bin/vemo task show 查看范围、风险和审批摘要。

日常闭环

git add src tests
python3 bin/vemo check --no-evidence
python3 bin/vemo verify
git add .vemo/evidence/T-feature.json
python3 bin/vemo check

最后一个命令必须返回 allow。deny 表示修复范围、秘密或配置问题；approval_required 表示必须由外部 CI/执行 Harness 注入审批，不能在任务文件中自授。

Claude Code 与 Git

安装器会合并 Claude PreToolUse hooks，并安装 Git pre-commit/pre-push 适配器。Hook 只是快速反馈，受保护分支上的 CI 才是服务端权威。重新打开 AI 助手后，确认项目已加载 .claude/settings.json。

审批环境变量

VEMO_APPROVED_TASK=<task id>
VEMO_APPROVED_TASK_DIGEST=<digest from task show>
VEMO_APPROVED_BY=<reviewer or trusted service>
VEMO_APPROVED_ACTIONS=<comma-separated action categories>

将这些值配置为受保护 CI 变量或由可信 Harness 注入，不要提交到仓库。

常用入口

目的命令
查看当前授权与决策python3 bin/vemo status
检查动作或 staged diffpython3 bin/vemo check
执行验证并写证据python3 bin/vemo verify
管理可选插件python3 bin/vemo plugin list
安装到其他仓库python3 plugins/setup/entry.py setup install /absolute/project --json

被拦截时

  • contract_unstaged：先暂存 policy/task 的修改。
  • verification_missing/stale：按当前 staged diff 重新运行 verify。
  • critical_approval_missing：获取外部审批并确认 task digest 未变化。
  • setup 冲突：处理预览列出的文件后重新预览；不要强制覆盖。
