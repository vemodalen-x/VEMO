VEMO 设计与治理边界

VEMO 把治理内核和产品能力分开：内核只决定一个 AI-authored diff 是否在授权范围内、是否通过验证；安装 UI、Fleet、报告、skills、automation 和 review 都是可选插件。

AI/Harness → PreToolUse hook → enforcement/core.py
                              ↓
                  Git hooks / CI adapter
                              ↓
                  snapshot-bound evidence → merge decision

五个强制概念

概念职责
Policy仓库规则、critical paths、拒绝动作、argv 验证命令
Task当前一次变更的 id、scope、risk 和审批摘要
Gate统一 evaluator 的 allow/deny/approval_required 决策
Verify实际执行 policy 命令
Evidence把 task、commands、exits 和 exact diff snapshot 绑定起来

安装服务职责

setup 插件负责 preview → apply → probe → manifest → recover/uninstall。它不产生第二套治理规则，也不能修改核心 evaluator。插件是可信本地代码，不是沙箱；默认全部禁用。

不负责什么

  • VEMO 不是 OS sandbox，不能隔离已被攻陷的主机。
  • VEMO 不自动设置分支保护、CODEOWNERS 或远端审批。
  • VEMO 不替代业务测试；业务验证命令由 policy 明确配置。
  • 插件不获得核心 policy authority，除非维护者明确启用并审查其本地代码。

完整边界和迁移说明见项目根目录的 SECURITY.md、docs/USAGE.md 和 docs/MIGRATION.md。
